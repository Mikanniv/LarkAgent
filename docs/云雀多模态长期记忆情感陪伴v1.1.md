## 用户注册

现在可以通过用户名和密码登录，用户名作为关键字，不能重复。密码使用哈希存储，每个用户拥有独立的日记和长期记忆库。日记存储在云端存储桶，长期记忆库仍采用本地存储实现。

## 云雀主动回复机制优化

为优化体验和降低成本，云雀不再每 2 分钟固定主动回复一次，而是每 $2^{i},i=1,2,3,\dots$ 分钟回复一次，上限为 128 分钟，即最久每隔约 2 小时主动发起一次回复。当情绪波动触发主动回复时，$i$ 重置为 1。

## 情绪总得分计算公式优化

考虑到实际应用场景很有可能存在缺失声音或视频模态的情况，v1.1 中，运用模态可用性掩码对情绪总得分 $\hat{f}$ 计算公式的结果进行归一化。设 $m_t、m_a、m_v ∈ \{0,1\}$ 表示文本、音频、视频模态是否可用，可用为 1，不可用为 0，则融合效价为：

$$\hat{f} = \frac{m_t w_t t + m_a w_a a + m_v w_v v}{m_t w_t + m_a w_a + m_v w_v}$$

当仅有单一模态可用时，$\hat{f}$ 退化为该模态的情感分数；当多个模态可用时，系统在可用模态之间重新归一化融合权重。若无可用模态，则不计算情绪分数。

## 参数优化

v1.1 仅对高敏感参数进行训练优化。其余记忆衰减、召回 top-k、置信度修正等低敏感参数沿用 v1.0 中的经验初始值，暂不作为本版本调参重点。

### 记忆召回相关参数

用户输入后，模型将检索记忆库中的记忆，并通过公式计算召回分数：
$$s=\alpha (1-d)+ \beta i+ \gamma r$$
其中，$d$∈\[0,1] 为归一化语义距离，$r$∈\[0,1] 为时间新近度，$\alpha$、$\beta$、$\gamma$为可配置权重，且$\alpha + \beta + \gamma = 1$，暂定 $\alpha=0.6,\beta=0.35,\gamma=0.05$。
最终召回得分最高的 top-k 条记忆，固定 k=3。

### valence 权重

在前文中，我们优化了预测的情绪总得分公式为
$$\hat{f} = \frac{m_t w_t t + m_a w_a a + m_v w_v v}{m_t w_t + m_a w_a + m_v w_v}$$
其中，设 $\theta_i$ 是可学习参数，则权重为：
$$w_i=\frac{e^{\theta_i}}{\sum_{j}^{} e^{\theta_j}} $$
用$\hat{f}$近似表示$valence$，即 $V_0 \approx \hat{f} $。
使用 CH-SIMS 中的单模态情感标注与多模态总标注，学习文本、音频及视觉单模态情感分数到多模态总情感分数的权重映射。得到的原始结果为 $w_t=0.2762,w_a=0.3336,w_v=0.3902$，最终令 $w_t=0.3,w_a=0.3,w_v=0.4$。

### AI记反馈与记忆更新

AI记在本系统中不直接作为面向回复生成的主召回记忆，而是作为一种中间整理层存在。系统会先根据当日对话、多模态情绪状态和用户日记生成结构化 AI记，用于归纳当前用户状态、重要事件、稳定模式、陪伴偏好和关系线索。AI记的主要作用不是直接参与 top-k 召回，而是为用户提供一个可阅读、可确认、可修正的“理解草稿”，使用户能够显式参与系统对自身状态的长期建模过程。

用户 review 之后，系统不仅只留下一句“用户修正了 AI记”，而是把修正结果真正分流到对应类型的长期记忆里：
- events -> event 记忆
- routines -> routine 记忆
- preferences -> preference 记忆
- relationships -> relationship 记忆

summary 只保留 AI记 本身的归档作用，不作为主召回内容

#### review 的 4 种操作

review 分为以下 4 类：
1. confirm：这条记忆的理解是正确的
2. correct：这条记忆的理解不正确，需要修改
3. delete：这条记忆不应该记下
4. append：需要新增一条记忆

#### 更新规则

##### 1. confirm
找到该 signal 对应的记忆，content 内容不变：

- content = content
- $confidence' = max(confidence_0, a)$
- $importance_0' = importance_0 + b$
- confirmation = confirmed
- 不新建重复 memory

其中，$a$、$b$ 是可配置参数，目前设定 $a=0.9, b=0.05$。

##### 2. correct

当用户明确说这条记忆不正确，并给出了正确版本时，执行 correct 操作。
找到该 signal 对应的记忆，用 after 替换原 content：

- content = after
- $confidence = c_1$
- $importance_0 = max(同类型记忆的importance_0)$
- confirmation = corrected

其中，$c_1$ 为可配置参数，目前设定 $c=0.90$。若找不到对应的旧记忆，则新建一条对应类型的记忆。

##### 3. delete

当用户说这条不该记时，执行 delete 操作：

- $confidence'=\lambda_c confidence$
- $importance_0'=\lambda_i importance_0$

其中，$\lambda_c、\lambda_i$ 是可配置参数，目前设定$\lambda_c=\lambda_i=0.5$，再由衰减机制自然删掉。

##### 4. append

当用户补充一条 AI记 没提到的新信息时，执行 append 操作
新建对应类型 memory：

- content = after
- confirmation = corrected
- source = diary_user
- $confidence = c_2$

其中，$c_2$ 为可配置参数，目前设定 $c=0.90$。

#### 写回时规则

##### document
不写成“用户修正了某天 AI记：……”，而是直接写成纠偏后的长期知识本身。
比如：
- event：用户已经成功保研。
- preference：用户喜欢不被过多打扰。
- relationship：用户对老师的催促较为敏感。

也就是说，after 应该尽量是最终可直接写入记忆的自然语言记忆，这样才方便后续召回。

##### source
每条 content 里有 evidence，写回 memory 时，source 优先按 evidence 判定值。如果 user_diary 非空，优先 source = diary_user，否则 source = conversation，模态可用性也直接复用 evidence.availability。

##### review 后 memory_ids 怎么写

```json
"memory_ids": {
  "preferences": [],
  "events": [],
  "routines": [],
  "relationships": [],
  "summary": []
}
```

每成功更新/新建一条 memory，就把它的 id 填到对应数组里,summary 只放 AI记 本身归档用的 memory id,主召回只看四类结构化 memory，不看 summary。
例如：

```json
"memory_ids": {
  "preferences": ["mem_pref_001"],
  "events": ["mem_event_004"],
  "routines": [],
  "relationships": [],
  "summary": ["mem_summary_020"]
}
```
